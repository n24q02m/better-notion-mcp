## 2025-02-14 - URL Obfuscation Prevention via comprehensive Unicode validation
**Vulnerability:** Invisible Unicode operators (like \u2060 Word Joiner, \u206F Nominal Digit Shapes) and special non-characters (\uFFFE-\uFFFF) were not blocked by `CONTROL_CHARS_REGEX`. This could potentially allow attackers to bypass URL validation for XSS payloads (e.g. `java\u2060script:alert(1)`).
**Learning:** Initial validation only blocked common whitespace, control, and directional characters but overlooked certain invisible separators and non-characters.
**Prevention:** Extend `CONTROL_CHARS_REGEX` in `src/tools/helpers/security.ts` to include `\u2060-\u206F` and `\uFFFE-\uFFFF`. Due to Biome lint rules rejecting control characters in regex literals (`noControlCharactersInRegex`), instantiate using `new RegExp()` with double-escaped strings to safely include these characters without triggering lint errors.
